### 1. [ponytail](https://github.com/DietrichGebert/ponytail) — 让 AI 写出"懒人代码"
⭐ 1,185 | Shell | 发布于 2026-06-12

**一句话亮点**：让 AI agent 像公司里最资深的老程序员——看五十行代码，一言不发，替换成一行。

**核心思路**：在写代码之前，先检查 6 层"能省则省"：
1. 这功能真的需要吗？ → 跳过（YAGNI）
2. 标准库有吗？ → 直接用
3. 平台原生功能？ → 直接用
4. 已安装的依赖？ → 直接用
5. 一行能搞定？ → 只写一行
6. 以上都不行 → 才写最小可用实现

**实测数据**：5 个日常任务 × 3 模型（Haiku/Sonnet/Opus），结果：
- 代码量减少 **80–94%**
- 成本降低 **47–77%**
- 速度提升 **3–6 倍**

每个"偷懒"处都有 `ponytail:` 注释，标注升级路径。

**安装方式**：
```bash
# Claude Code
/plugin marketplace add DietrichGebert/ponytail
/plugin install ponytail@ponytail
```

### 2. [architect-loop](https://github.com/DanMcInerney/architect-loop) — 跨厂商 Agent 开发循环
⭐ 285 | HTML | 发布于 2026-06-12

**一句话亮点**：Claude Fable 5 负责架构与评审，GPT-5.5 Codex 负责实现，仓库本身充当记忆系统。

**核心架构**：
- `/architect` — 构建循环：Fable 先写 spec 和验收门（gates），Codex 在隔离的 git worktree 中并行构建，Fable 独立运行门命令并判断是否通过
- `/architect-research` — 研究循环：先用廉价 Codex scout 扫描主题（~10 次搜索），Fable 设计 3–6 条调研路线，并行研究员运行严格预算限制，最终 Fable 验证并输出决策导向报告

**最大特点**：仓库是唯一记忆载体，不在仓库里 = 没发生过。

**安装方式**：
```bash
git clone https://github.com/DanMcInerney/architect-loop
cd architect-loop && ./install.sh
npm i -g @openai/codex@latest  # Codex CLI >= 0.133
```
