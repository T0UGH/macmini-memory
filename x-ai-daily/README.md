# X AI Daily

Daily X/Twitter AI intelligence reports.

## Defaults
- Timezone: Asia/Shanghai
- Delivery time: 08:30 daily
- Lookback window: 48 hours
- Surface delivery: Feishu summary only
- Archive: full markdown in this directory
- Focus: all AI news, with emphasis on Claude ecosystem, agents, and coding
- Method: watchlist accounts + keyword tracking
- Git policy: auto commit + push
- Output language: Chinese-first
- Do not produce a pure English deliverable
- English can appear only for names, handles, product names, and brief quoted source text when necessary

## Core writing rule
Do not write the daily report as a second-hand abstract.
Each important item must clearly separate:
1. what the original post/source actually said,
2. what your interpretation is,
3. why it matters now.

Bad:
- one short summary line + a long macro judgment

Good:
- original key points
- one short source quote when useful
- your judgment
- why it matters
- what to do next / whether to click through

## Required item structure
Each major item should include these fields when possible:
- 作者
- 来源
- 链接
- 原文要点（3-5 条，尽量写具体动作/能力/限制，不要空泛）
- 原话摘录（1 条最关键原文；可短）
- 我的判断（你的分析，和原文事实分开）
- 为什么重要（对工作流/行业/用户的意义）
- 建议动作（值得点开 / 建议细看 / 可略过 / 持续跟踪）
- 评分

## TL;DR rule
Feishu summary should not only say “发生了什么 + 为什么重要”.
For top items, it should try to preserve one concrete source detail, so the summary is not just abstract commentary.

## Scoring dimensions
Each item should include:
- Importance
- Technical Depth
- Practical Value
- Relevance to user
- Programmer Survival Index

## File naming
- Daily report: `YYYY-MM-DD.md`
- Optional config/reference files live beside this README.

## Author + link rules
- Full markdown items must include the original author handle when available.
- Feishu summary should stay concise and include the GitHub report link at the end for full reading.
- If the source tool cannot resolve an author handle, prefer a best-effort lookup before publishing.
