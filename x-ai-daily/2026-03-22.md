### 3) Claude Code Desktop 可直接点选 DOM：拿到结构、样式、截图，React 还给源码定位
- 作者：@lydiahallie
- 来源：Claude Code / desktop / frontend editing
- 链接：https://x.com/lydiahallie/status/2035088515332284651
- 原文要点：
  - Claude Code Desktop 现在允许在预览中 **直接选择 DOM 元素**，不必再靠文字描述“页面上那个按钮/卡片/区域”。
  - Claude 获取的不只是元素名字，还包括 **tag、classes、关键样式、surrounding HTML**。
  - 同时会附带该区域的 **cropped screenshot**，让模型看到更具体的视觉上下文。
  - 如果目标是 **React app**，还会额外给到 **source file、component name、props**。
  - Lydia 在回复里确认该能力 **只在 desktop**，并且 **不需要额外浏览器扩展**，直接内建在 Preview panel 里。

- 为什么重要：对多步 coding / automation 流程来说，10 倍冷启动改进会改变很多工作流是否“值得拆成子任务”。以前嫌慢的技能化、子代理化、工具化调用，现在会更接近实时体验。

## 4. 观点 / 判断
- 这 48 小时最明显的趋势不是某个模型成绩，而是 **agent workflow 的运行面被产品化**：Claude 在做 channels、scheduled tasks、DOM 选取、effort；OpenAI 在做容器冷启动；Vercel 在做框架级 rails；Codex 在做桌面入口。
- Claude 生态这轮强在“表层入口”和“底层执行”同时推进：
  - 表层入口：Telegram / Discord、桌面预览点选、Web 定时任务；
  - 底层执行：effort 下沉、权限中继、脚本 bare 模式、worktree 恢复。
- OpenAI/Vercel/Codex 的方向分别很清晰：
  - OpenAI 补 **agent infra latency**；
  - Vercel 补 **agent-native framework context rails**；
  - Codex 补 **系统级入口与窗口调度**。
- 如果把这些信号放一起看，未来一个月最值得盯的不是单次 benchmark，而是：
  - 谁能让 agent **在后台稳定运行**；
  - 谁能给 agent **更准确的 UI/代码上下文**；
  - 谁能把 **容器、权限、入口、文档版本** 这些摩擦一起抹平。
