- 来源：Claude / Cowork / agent workflow

### 4) NVIDIA OpenShell 把“agent 安全运行时”单独产品化：夹在 agent 与基础设施之间做治理
- 作者：@NVIDIAAIDev
- 来源：Agent runtime / safety / infra
- 链接：https://x.com/NVIDIAAIDev/status/2034268585799913730
- 原文要点：
  - NVIDIA AI Developer 发布 **NVIDIA OpenShell**，定位是一个开源 runtime，用来让 claw / autonomous agents 更安全。
  - 官方说它会放在 **agent 和基础设施之间**，负责治理 **agent 如何执行、能看见什么、能做什么、推理发往哪里**。

### 5) Claude Code skill 支持 `!` 命令注入动态内容：技能不再只能吃静态说明书
- 作者：@lydiahallie
- 来源：Claude Code / skills / workflow
- 链接：https://x.com/lydiahallie/status/2034337963820327017
- 原文要点：
  - Lydia Hallie 提醒，如果某个 skill 依赖动态内容，可以在 **SKILL.md** 里嵌入 **`!\`command\``**。
  - Claude Code 会在 **skill 被调用时先执行 shell 命令**，然后把输出 **内联替换** 回 prompt。
  - 模型实际看到的是命令结果，而不是原始 shell 语法。
  - 这让 skill 能在执行时临时注入环境信息、仓库状态、生成内容，而不必把所有上下文事先硬编码。
  - 同时也意味着 skill 设计会更像“轻量 workflow”而不只是静态提示模板。
- 原话摘录："Claude Code runs it when the skill is invoked and swaps the placeholder inline, the model only sees the result!"
- 我的判断：这是很实用但也很容易被低估的工作流升级。它把 skill 从“文档化提示词”推进到“可在调用时动态取数的能力包”。但另一面也很明显：一旦大家开始把 shell 注入到 skill 里，**可预测性、安全边界、幂等性** 会马上变成设计重点。
- 为什么重要：贵平很在意规则、配置、验证、可复用流程。这个能力正好处在那条线上：skill 终于能少一点死文档，多一点实时上下文，但也更需要工程化约束。

- 作者：@GoogleCloudTech

- 为什么重要：贵平长期在看 coding agent / OpenClaw / skills，这正是方法论层的关键分界线。理解这个分层，能更快判断一个 agent 产品到底是“会接工具”还是“真能交付结果”。
