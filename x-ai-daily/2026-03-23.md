- 作者：@lydiahallie
- 来源：Claude Code / desktop / frontend editing
- 链接：https://x.com/lydiahallie/status/2035088515332284651
- 原文要点：

  - 同时会附带对应区域的 **cropped screenshot**，把视觉上下文一起送进去。

### 8) Claude Code 的安全边界被现实补课：CVE-2026-33068 说明 agent 工具首先还是软件系统
- 作者：@secharvesterx
- 来源：Claude Code / security advisory / workspace trust
- 链接：https://x.com/secharvesterx/status/2035053907433435530
- 原文要点：
  - X 上出现对 **CVE-2026-33068** 的集中转发与提醒。
  - 该问题描述非常具体：**workspace trust dialog bypass via repository settings loading order**。
  - 受影响范围写明是 **Claude Code prior to 2.1.53**。
  - 触发点与仓库内 **`.claude/settings.json`** 相关，本质是设置在 trust dialog 前被解析。
  - 这不是“模型胡说八道”类风险，而是很典型的 **配置加载顺序 / 权限边界** 软件漏洞。
- 原话摘录："Claude Code workspace trust dialog bypass via repository settings loading order [CVE-2026-33068, CVSS 7.7]."
- 我的判断：这条特别值得写进日报，因为它提醒大家：agent coding 工具再“智能”，也先是本地高权限软件。真正的高风险点很多时候不是模型推理，而是设置文件、信任边界、仓库内容、工具调用权限这些老派软件工程问题。
- 为什么重要：对高频使用 Claude Code / OpenClaw / MCP 的用户来说，权限边界和加载顺序失守，风险比一次回答质量下降严重得多。尤其当工具越来越能执行 shell、读文件、调用网络时，这类漏洞会直接触达本机安全。
