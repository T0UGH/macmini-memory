### 5) Claude Code 2.1.85 的高价值细节开始落在 hooks、定时任务与组织策略上
- 作者：@oikon48
- 来源：Claude Code / community changelog recap
- 链接：https://x.com/oikon48/status/2037313024793673930
- 原文要点：
  - Oikon 汇总 **Claude Code 2.1.85** 变更，其中最关键的是 **Hooks 新增 `if` 条件字段**，而且可直接使用权限规则语法，例如 `Bash(git *)`，用来过滤 hooks 触发时机并减少进程开销。
  - **`/loop` 与 `CronCreate`** 触发的 scheduled tasks，现在会在 transcript 里加入 **timestamp marker**。
  - 组织策略层新增更硬的约束：若某插件被 **`managed-settings.json`** 屏蔽，就**不能安装或启用**，且会从 marketplace 视图中隐藏。
  - **PreToolUse hook** 现在可返回 `permissionDecision: "allow"` 和 `updatedInput`，从而对 `AskUserQuestion` 作答，支持更像 headless integration 的自定义 UI 流程。
  - 另外还修了几个重度用户会实际踩到的问题：大上下文下 `/compact` 失败、Kitty keyboard protocol 退出残留、以及大仓库 `@` 文件补全性能。
- 原话摘录："Hooksにパーミッションルール構文（例: `Bash(git *)`）を使用した条件 `if` フィールドを追加。"
- 我的判断：这不是 headline 级大功能，但很像 Claude Code 正在补齐“**重度使用后才暴露出来的工程边角**”。hooks 条件、定时任务时间标记、组织级插件封禁、headless 问答接入，这些都不是 demo 功能，而是把 Claude Code 推向更复杂团队环境时必须有的零件。
- 为什么重要：贵平关心的是 agent/coding workflow 的真实可落地性，不是热闹演示。像 hooks 条件和组织策略这类能力，决定的是能不能把 Claude Code 稳定嵌进已有团队流程，而不是只在个人机器上玩得顺。

### 6) LangChain JS 把 agent orchestration 往后台并行推：async subagents + 多模态 read_file 一起到位
- 作者：@LangChain_JS
- 来源：deepagentsjs / orchestration / multimodal tooling
- 链接：https://x.com/LangChain_JS/status/2036877476413268029
- 原文要点：
  - **deepagentsjs v1.9.0 alpha** 发布。
  - 最大更新是 **Async subagents**：可以启动后台子任务，同时用户继续和主 agent 交互。
  - 该能力还包括两个工作流细节：可**控制后台任务生命周期**，并在完成时收到**automatic completion notifications**。
  - 底层 backend 也做了 refactor，改成 **BackendProtocolV2**。
  - 直接结果是 `read_file` 开始能处理 **images、PDFs、audio、video** 作为多模态内容块；同时官方还说对 **Claude models 的 prompt caching** 做了性能改进。
- 原话摘录："Async subagents - kick off background tasks via asynchronous subagents that run while you continue to interact with the primary agent."
- 我的判断：这条反映的是 agent 框架层正在从“单线程对话”往“**前台交互 + 后台执行并存**”迁移。谁先把后台任务生命周期、通知、文件多模态读取这些底座做好，谁的 agent 框架才更像真实工作系统，而不是聊天 demo。
- 为什么重要：子 agent 能不能异步跑，决定了 agent 能否自然处理耗时任务；`read_file` 多模态化则直接扩大了它可吃的工作对象范围。对于构建长期 agent workflow 的人，这比又多一个 benchmark 更有长期意义。
