# GitHub AI Daily（2026-03-17）

## 核心仓库

### anthropics/claude-code · v2.1.77
- 发布时间：2026-03-17 08:28（北京时间）
- 这版不是小修小补，而是把 Claude Code 在长会话、tmux、权限与恢复链路上的几个高频痛点一起收拾了一遍。
- Claude Opus 4.6 默认最大输出上限提到 64k，Opus 4.6 / Sonnet 4.6 的上限提到 128k，长任务和长代码生成空间更大了。
- 新增 `allowRead` 沙箱文件系统设置：可以在 `denyRead` 的大区块里对局部目录重新开白名单，权限控制更细。
- `/copy` 现在支持 `/copy N`，可以直接复制倒数第 N 条 assistant 回复，回收历史输出更方便。
- 修复 `--resume` 在近期历史加载上的截断问题；大 session 的恢复速度也继续优化，官方给出的量级是最高约 45% 更快、峰值内存下降约 100-150MB。
- 修复 tmux 下的多个细节问题，包括剪贴板复制失败、背景色渲染异常、通过 tmux/screen 启动时 IDE 集成不能自动连接等。
- 修复 PreToolUse hook 返回 `allow` 时可能绕过 `deny` 规则的问题，这条对企业权限策略尤其关键。
- 链接：https://github.com/anthropics/claude-code/releases/tag/v2.1.77

### sst/opencode · v1.2.27
- 发布时间：2026-03-16 10:34（北京时间）
- 这版 OpenCode 的重点很明确：修会话、修 worktree、补长任务稳定性，而不是堆新能力。
- 修复 worktree 与孤儿分支场景下的 session 丢失问题，这条对多分支并行工作流最有价值。
- 默认 chunk timeout 从 2 分钟提高到 5 分钟，长步骤执行更不容易被误判超时。
- 明确把 compaction message 记为 agent initiated，说明它在继续补齐会话状态与压缩链路的一致性。
- 清理 legacy permission module，并重构 QuestionService / PermissionNext 相关实现，偏底层治理，方向是把权限与提问流程做得更稳。
- Desktop 侧补了 multiline web paste，prompt composer 输入体验更完整。
- 链接：https://github.com/anomalyco/opencode/releases/tag/v1.2.27

### 1. phodal/routa
- 简介：一个多 Agent 协调平台：把用户意图解析成结构化规格，再通过 MCP / ACP / A2A 协议把任务路由给 Claude Code、OpenCode、Gemini 等工具。
- 与主线关系：它命中的不是“单个 agent 很强”，而是多 agent 之间的协议层和路由层，这和 Claude Code / OpenClaw 往编排与协同扩展的方向直接相关。
- 为什么现在值得看：大家都在做 agent，但真正能把 ACP / MCP / A2A 这些接口串起来的中间层还不多，它属于值得持续盯的基础设施苗子。
- 成熟度判断：Stars 152，还是早期项目，更像方向验证而不是现成生产方案。
- 建议动作：先纳入观察名单，重点看它后续是不是能把协议抽象和真实工具接入做扎实。
- 链接：https://github.com/phodal/routa

- 为什么现在值得看：如果 ACP 不只服务 coding，而能进入笔记、知识库和个人信息流，整个 agent 使用边界会明显扩大。
- 成熟度判断：Stars 1218，已经超过纯 demo 阶段，至少说明这个接入方向有真实需求。
- 建议动作：值得做一次轻量试用，重点看 ACP 接入后的上下文切换成本和稳定性。
- 链接：https://github.com/RAIT-09/obsidian-agent-client

### 4. penso/arbor

### 5. open-gitagent/gitclaw
- 简介：一个 git 原生的 AI agent 框架：身份、规则、记忆、工具和 skills 都作为版本化文件存放在仓库里。

- 为什么现在值得看：repo-native memory / rule system 这条线很可能会变成后续 agent 可移植性和可审计性的关键基础设施。

- 建议动作：纳入长期观察；如果后面它把记忆、规则、版本控制之间的关系做实，可以再考虑深挖。
