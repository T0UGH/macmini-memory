# 日报产出规则（记录于 2026-03-17）

目标：以后每天稳定产出 4 份内容，不再靠临场理解。

## 一、四份固定产物

### 1. X 日报完整版
用途：贵平自己看、存档、回查。
要求：保留高信息密度、链接、判断、来源。

### 2. GitHub 日报完整版
用途：贵平自己看、存档、回查。
要求：不能只有方向摘要；对核心仓库必须补“具体更新点中文整理”。

### 3. X 日报小红书版
用途：外发。
要求：1179x1200；多张短图；信息密；少空话；别人不看原日报也能看懂。

### 4. GitHub 日报小红书版
用途：外发。
要求：1179x1200；多张短图；重点是“更新了什么”的中文信息卡片，不是抽象趋势判断。

## 二、X 日报小红书版规则
- 默认尺寸固定：1179x1200
- 不做超长图
- 宁可多图，也不要单图过长
- 每张图必须有足够信息密度，减少空白
- 每张图都应当让陌生人单独看懂
- 可用结构：封面 / 重点事件 1 / 重点事件 2 / 重点事件 3 / 配套工具 / 风险提醒

## 三、GitHub 日报完整版修法
GitHub 完整版不能只保留“方向摘要”，必须对核心仓库增加“更新点中文整理”。

### 核心仓库（当前）
- anthropics/claude-code
- openclaw/openclaw
- sst/opencode
- zed-industries/zed

### 每个核心仓库至少包含
- 仓库名
- 版本号
- 发布时间
- 3-8 条“具体更新点中文整理”
- 可选：一句“为什么值得看”

注意：这里的“具体更新点”不能只来自日报摘要，必须来自 release/changelog 原文。

## 四、GitHub 日报小红书版规则
不能直接从 GitHub 日报摘要版生图，必须走以下流程：
1. 先从 GitHub 日报中选出重点仓库
2. 再抓对应 release/changelog 原文
3. 把具体更新点翻成中文
4. 再排成信息卡片

### 单仓库卡片格式
- 仓库名
- 版本号
- 发布时间
- 更新了什么（中文 3-6 条）
- 最多一句“这意味着什么”

### 候选仓库卡片格式
- 仓库名
- 一句话简介
- Stars
- 为什么值得点开
- 新仓候选卡片不能只写一句话简介；至少包含：仓库名、Stars、它解决什么问题、核心做法/关键词、为什么值得看、与 Claude Code/OpenClaw/Codex 主线的关系、建议动作（现在看/长期跟/先收藏）。

## 五、明天执行顺序（硬流程）
1. 先生成 X 日报完整版
2. 再生成 GitHub 日报完整版（含核心仓库更新点中文整理）
3. 再生成 X 日报小红书版
4. 再生成 GitHub 日报小红书版
5. 出图前强校验

## 六、出图前强校验
### 校验 1：尺寸
- 小红书图必须是 1179x1200

### 校验 2：留白
- 每张图不能太空；信息密度必须足够

### 校验 3：内容类型
- X 小红书图：陌生人能看懂
- GitHub 小红书图：必须是具体更新内容，不是泛泛总结

### 校验 4：内容来源
- GitHub 卡片中的更新内容必须来自 release/changelog 原文，而不是空泛概括


## 七、GitHub 小红书版新增版式规则（2026-03-17 晚）
- 不要封面页；第一页直接从 `Claude Code` 卡片开始。
- 不要 `Zed` 单独卡片，默认从 GitHub 小红书外发版中移除。
- GitHub 小红书版默认顺序：Claude Code → OpenClaw → Codex → OpenCode → 候选仓库/继续跟进名单。
- 长期跟进仓库名单里：加入 `Codex`，去掉 `Zed`。
