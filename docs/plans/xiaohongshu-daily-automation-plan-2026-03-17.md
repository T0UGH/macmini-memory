# 小红书日报自动化思路（记录于 2026-03-17）

## 目标
每天自动产出并尽量自动发布两条小红书：
1. X AI Daily
2. GitHub AI Daily

要求：
- 不是 markdown 长截图，而是适合小红书阅读的多图内容
- 统一风格、适合手机阅读
- 最终最好能用贵平自己的账号自动发布

## 内容流水线设计
1. 现有日报生成（X / GitHub）
2. 从日报中提炼适合小红书的内容结构
3. 生成多图卡片（封面 + 摘要 + 分页正文）
4. 生成标题、正文、标签
5. 自动发布到小红书（条件：登录态可用）
6. 把发布结果和链接写回记忆仓库

## 图片形态建议
每条笔记 4-6 张图：
- 图 1：封面（主题 + 日期）
- 图 2：今日结论 / 三个重点
- 图 3-5：展开内容（每张图只讲 1-2 个点）
- 图 6：行动建议 / 值得关注对象（可选）

不建议继续使用“完整 markdown 长图”作为小红书主内容，因为太长、平台感弱、转化低。

## 两条日报的内容定位
### X AI Daily
适合做成：
- 今日 AI 讨论热点
- 3-5 个高信号观点
- 更偏“信息摘要型笔记”

### GitHub AI Daily
适合做成：
- 今日值得看的 repo / 工具
- 3-5 个核心项目
- 每个项目一句话判断
- 更偏“工具发现型笔记”

## 自动发布的前提条件
要实现“自动发到小红书”，需要：
- 小红书账号登录态（cookies / 会话）
- 可用的发布工具链
- 图片本地路径 + 文案 + tags 组装能力

## 当前已知技术线索
- Agent Reach skill 文档显示：存在 `xiaohongshu.publish_content(title, content, images, tags)` 这类能力。
- 该能力依赖登录态，文档提示需要通过 Cookie-Editor 导入 cookies。
- 因此自动发的关键不在“是否支持发”，而在：
  1. 登录态获取与维持
  2. 本地图文产物生成稳定
  3. 发布失败后的重试/记录

## 推荐落地顺序
### Phase 1：先做内容生产系统
- 生成小红书风格多图
- 生成标题/正文/标签
- 每天把产物写入记忆仓库，供人工审阅

### Phase 2：再接自动发布
- 接入贵平账号登录态
- 自动上传图片并发布
- 写回发布状态（成功/失败/链接/时间）
